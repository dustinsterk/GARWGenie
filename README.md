# GARW Genie

![GARW Genie](assets/garw_genie_logo_dark.png)

(Settings live in `~/.garw_genie/`; older folders are migrated automatically. Artwork in `assets/` is generated by `assets/make_logo.py` from the Press Start 2P glyphs — edit its PALETTE or FONT and re-run to change it; PNG, SVG and .ico are regenerated.)

Manage dash screens on a GARW device over SSH — from a .zip or straight from GitHub.
Runs on Windows, macOS and Linux with Python 3.8+; standalone builds below need no Python at all.

```
pip install -r requirements.txt      # just paramiko; GitHub access uses the standard library
python garw_genie.py              # opens the window
```

Join the **GARW** Wi-Fi network first. The tool warns if it sees a different SSID and refuses
to act if the unit does not answer on 192.168.42.1:22.

## Two networks, one workflow

The unit's **GARW** Wi-Fi has no internet, so the tool is built around a two-step rhythm. A background
monitor watches your Wi-Fi SSID, the unit and the internet every few seconds and shows both as pills in
the header — **Internet** (with the SSID you're on) and **IC7**. Recent macOS hides the Wi-Fi name from apps without Location Services permission (`<redacted>`); the tool then asks `system_profiler` for it, and whenever the unit itself answers it simply reports GARW. The moment the unit answers after you join
GARW, every tab refreshes itself from the device (dashes, settings files, system info, GitHub status);
the moment internet appears and repos are tracked (and haven't been checked in the last 30 minutes), GitHub is checked and the cache filled. No clicking
required — the buttons remain for manual refreshes. Until the unit answers, every tab except GitHub repos is locked (greyed out) — clicking one shows a brief tooltip and blinks the reason under the repo list — so the app opens on the one thing you can do off-GARW: manage and download repos.

1. **On the internet** — GitHub repos tab → *Check & download updates*. Every tracked repo's latest
   commit is fetched from GitHub and the dash is stored in a local cache (`~/.garw_genie/cache`).
2. **On GARW Wi-Fi** — everything else: install the cached dashes, manage settings files, upload zips,
   flash firmware. Nothing in these steps needs the internet.

## The tabs

**GitHub repos** — the list starts from **`default_repos.txt`** (next to the script / executable): one URL per line, `#` for comments — edit it to change the bundled default dashes; new lines are picked up on the next launch and repos you remove in the app stay removed. *Add repo…* with a URL like `https://github.com/owner/GTDash` (a `/tree/branch`
suffix pins a branch). The repo is looked up, downloaded and validated before it's accepted — one that doesn't hold a v5 dash (`<Name>.qml` + `<Name>.qml.png` at the root, or one folder per dash) is refused with the reason. Offline, it's added unchecked and validated on the next check; a tracked repo that later stops validating shows a red *Not a v5 dash repo* status. The table shows the latest commit, whether it is **Downloaded** to the cache,
and the **Status** against what the unit reports: *Not installed*, *Up to date*, or
*Update a41c9d2 → 3f2a9c1 · ready* (or *· download first* if the cache is stale). *Install / update
selected* (or double-click) installs from the cache; offline it will tell you plainly if a repo hasn't
been downloaded yet. *Install all updates* does every cached repo that is new or behind.

**Device Dashes** — *Refresh* lists every dash in `/opt/IC7/library` with a validity check (`<Name>.qml` +
`<Name>.qml.png`), file count, and for GitHub-installed dashes the repo, commit and install time.
*Delete selected…* removes dashes (one confirmation, verified gone). *Reboot device* sends `reboot now`.

**Dash Settings** — per-dash settings live in `/opt/IC7/screen_configs/<file>`; each dash names its
file inside its own `.qml` (`gtdash_config.txt`, `LFA_config.txt`, `Outrun.txt` …). *Refresh* lists them
with size, modified time and the dash that uses each; a file a dash expects but that doesn't exist yet
shows greyed as *missing*. Click a file to open it in the editor on the right. Beside every line the gutter names the QML property that line feeds, read live from the owning dash's `.qml` on the unit (`root.coolantHigh = pF(rline(8), …)` and `configstring[4] = root.waterlow` styles are both understood), and the detail line under the editor shows the property's type, declared default and current value for the line under the cursor. Edit, then *Save to unit* (⌘S / Ctrl+S) or *Revert*. Saving or uploading settings never reboots the unit: the dash re-reads its file on a screen change, so the tool flips the dash Right and back Left with the controller instead. *Download selected…* / *Download all…* save copies
to a folder (a timestamped `IC7_screen_configs_…` folder for "all"); *Upload files…* pushes local files
back, asking before overwriting.

**Upload .zip** — manual route: pick a zip of one dash or many, validated on the spot, *Upload to IC7*.

**Firmware / System Info** — left side, *Read system info*: firmware version and install layout, bootloader,
whether the IC7 process is running, OS, kernel, Qt, CPU model / cores / clock / temperature, RAM,
storage, uptime and load, clock, IP/MAC, and whether `ccrypt` is present.
Right side, the updater: pick a GARW package (a `.zip` holding `<name>.tar.cpt`, or the `.tar.cpt`
itself) and *Install firmware…*. The package is uploaded to `/mnt` on the unit (the stock updater's
scratch area), decrypted **on the unit** with `ccrypt -d -K <PASS>`, unpacked, and its own `run`
installer executed — the same thing the USB updater does. Size is verified after upload, free space is
checked first, the `run` script must exist before anything is touched, and the new binary version is
read back afterwards. Works on v4 units (it is how you get to v5). If the unit lacks ccrypt, a local
`ccrypt` is used instead and the plain tar uploaded. The v4→v5 package leaves the old `/opt/Garw_IC7`
in place; the tool offers to remove it after a successful update so the unit is in the clean v5 layout.

**Controller** — the old phone app's D-pad, over Wi-Fi (UDP to 192.168.42.1:1234, the protocol from
GARWController.js). Click the pad or use the keyboard while the tab is showing: arrow keys move
(hold one and the value under the cursor steps quickly — "Repeat taps", rate adjustable, default 5 taps/s — or switch
to "Hold" for a single long press), **S** runs the GARW-settings sequence (Left held 3 s, then Right),
**L** / **R** hold Left / Right for 3 s to enter the OS main settings, **Esc** releases everything.
The unit keeps the last button state until the next packet, so while idle the tool sends "no button"
every 200 ms — the heartbeat from the original script — and a lost release can never leave a key stuck.
The controller is only active while its tab is showing.

The **Reboot after changes** checkbox (top right) applies to uploads, installs, deletes and settings
uploads; a firmware update always reboots.

The window uses a dark theme with GARW orange for primary actions; colours live in `PALETTE`. An **8-bit font** checkbox in the header switches the whole UI to **Press Start 2P**, the bundled pixel font (`assets/PressStart2P.ttf`, SIL OFL — see `assets/PressStart2P-LICENSE.txt`); it's off by default and the app restarts to apply it. The font is registered for the app's own process at launch (GDI on Windows, CoreText on macOS, `~/.fonts` on Linux), so nothing needs installing.

## How GitHub tracking works

A dash installed from GitHub carries a small hidden file, `/opt/IC7/library/<Name>/.garw_source.json`:

```json
{ "url": "https://github.com/owner/GTDash", "branch": "main",
  "sha": "3f2a9c1…", "commit_date": "2026-09-22T12:00:00Z", "installed": "2026-09-23T…", "dash": "GTDash" }
```

That is the source of truth for "what's installed", so any laptop running the tool gets the same
answer, and a dash uploaded manually from a zip shows as *manual upload* with no version.
Hidden files are ignored by the IC7 binary.

Repo layout — one dash per repo, named after the `.qml`, not the repo:

```
GTDash (repo)
├── GTDash.qml          ← dash name comes from this
├── GTDash.qml.png
├── assets/…
├── README.md, LICENSE  ← uploaded too (harmless)
└── .gitattributes      ← hidden files are never uploaded
```

A repo holding several dash folders (`LFA/LFA.qml`, `Outrun/Outrun.qml`, …) also works. Extra component `.qml` files, `.frag` shaders, fonts and images are all fine — only a `.qml` with a matching `.qml.png` counts as the dash. A repo (or zip) still in the **v4 layout** — `<Name>.qml` loader plus `<Name>_main.qml` / `<Name>_main.qml.png` — is refused with a message saying the dash hasn't been merged to v5 yet.

GitHub allows 60 unauthenticated API calls per hour per IP. The tool is frugal with them: repeat checks send
the stored ETag and GitHub's "304 Not Modified" answer is free, the automatic check when internet appears
only runs if the last check is more than 30 minutes old (`auto_check_minutes` in `config.json`, 0 disables),
and the log prints the remaining budget after each check. For 5,000 requests/hour, press **GitHub token…** on the repos tab and paste a personal access token (public repos need no scopes; it's stored in `config.json`, or set the `GITHUB_TOKEN` environment variable). If you ever hit that, put a personal-access token in `config.json` as
`"github_token"` or set the `GITHUB_TOKEN` environment variable — public repos need no scopes.

## Zip layout

One folder per dash, each with the two required files. Other assets are uploaded as-is.

```
MyDash.zip                 Screens.zip              library.zip (Finder "Compress")
└── MyDash/                ├── GTDash/              └── library/
    ├── MyDash.qml         │   ├── GTDash.qml           ├── GTDash/…
    ├── MyDash.qml.png     │   └── GTDash.qml.png       └── LFA/…
    └── assets/…           └── LFA/…
```

A Finder-style wrapper folder is detected and skipped as long as it holds only dash folders.
`__MACOSX/`, `.DS_Store`, `.git*`, `.garw_migration_backup/` and anything else dot-prefixed is
never uploaded; the log itemizes what was dropped. If any dash in a zip fails, nothing is uploaded.

## Firmware gate

| On the unit | Meaning | Result |
|---|---|---|
| `/opt/IC7/bin/IC7` | v5 or newer | continue |
| only `/opt/Garw_IC7/bin/Garw_IC7` | v4 | abort — update the unit first |
| neither, or both | not a GARW IC7 / unexpected state | abort |

The float32 version literal in the binary (`od -A n -t f4 -j 57832 -N 4 /opt/IC7/bin/IC7`,
falling back to offset 56808) is shown in the log when readable; a value below 5 also aborts.

## Upload mechanics

Files go over SFTP into a hidden staging folder and are renamed into place, so a dropped Wi-Fi
link never leaves a half-written dash. Existing dashes are replaced after one confirmation that
lists them. `chmod -R a+rX` + `sync`, then the `.qml` and `.png` are verified present.

## Command line

```
python garw_genie.py MyDash.zip --cli            # upload, then reboot
python garw_genie.py --list                      # what's on the device
python garw_genie.py --delete Outrun LFA -y      # delete, then reboot
python garw_genie.py --reboot
python garw_genie.py --add-repo https://github.com/owner/GTDash
python garw_genie.py --check-repos               # compare GitHub vs device
python garw_genie.py --install-repo https://github.com/owner/GTDash -y
python garw_genie.py --list-configs                     # settings files + which dash uses them
python garw_genie.py --download-configs ./backup        # save them all
python garw_genie.py --upload-configs gtdash_config.txt -y
python garw_genie.py --sysinfo                          # OS / CPU / RAM / storage from the unit
python garw_genie.py --install-firmware version_V4toV5.zip -y
       after dash changes the app restarts by default; --reboot-after reboots instead, --no-reboot does nothing
       --check-repos needs internet (it also fills the cache); --install-repo works offline from the cache
```

## Standalone executables (no Python needed by the user)

PyInstaller bundles everything into one app. It cannot cross-compile, so each platform's build
runs on that platform.

**On a Mac:** `./build.sh` → `dist/GARW Genie.app` (+ `GARW-Genie-macOS.zip`).
**On Windows:** `build.bat` → `dist\GARW Genie.exe`.
The app icon (`assets/garw_genie_icon.png`, a pixel “G” tile) is turned into an `.icns` by `build.sh`; `assets/garw_genie.ico` is used on Windows.

**Or let GitHub build both:** push this folder to a repo — `.github/workflows/build.yml` builds the
.exe and .app on every push (Actions → artifacts); pushing a tag such as `v2.0.0` publishes a
Release with both attached.

Unsigned builds trigger first-run warnings: macOS Gatekeeper (right-click → Open, or
`xattr -dr com.apple.quarantine "GARW Genie.app"`) and Windows SmartScreen (More info → Run anyway).
An Apple Developer ID / Windows code-signing certificate removes them; `build.sh` prints the `codesign` line.

## SSH login

The header has **SSH login** fields for the unit's SSH username and password (default `root` / `root`; the eye
button reveals the password). Changing them saves to `config.json` (`ssh_user`, `ssh_password`) and
reconnects immediately. A wrong login shows one clear message and the status pill reads
"login failed" until the fields are corrected — it does not keep retrying in the background.
The CLI uses the same saved values.

Beside it, **GARW Wi-Fi** holds the unit's hotspot name and password (default `GARW` / `garwicxX`, saved as
`wifi_ssid` / `wifi_password`). The SSID is what the monitor and every message refer to. **Join** asks the
OS to connect to that network (`networksetup` on macOS, a WPA2 profile + `netsh wlan connect` on Windows,
`nmcli` on Linux); if the OS refuses, it says so and you join from the system Wi-Fi menu as before.

Both boxes and **Join** are greyed out while the GARW device is connected (changing them mid-session would
only break a working link) and become editable again as soon as the unit drops off.

## Log file

Everything the app does is appended to `~/.garw_genie/logs/garw_genie.log` (rotated daily, 30 days kept;
the **Logs…** button next to the progress bar opens the folder). Every line you see in the on-screen log
is there with a timestamp, plus every SSH command sent to the unit (`SSH$ …`, with non-zero exit codes and
stderr), every SFTP transfer (`SFTP put/get …`) and firmware steps — so any change to the GARW filesystem
(installs, deletes, settings saves, restarts) can be traced exactly. The firmware password is masked.

## Settings

Host, credentials, library path and the firmware gate are constants at the top of
`garw_genie.py`. Tracked repos and preferences live in `~/.garw_genie/config.json`.
